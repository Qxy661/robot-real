# 实机深化路线 · 差异化作品集产出

> **给 Ubuntu 环境的 Claude。** 在基础落地（实机交接-ubuntu.md）之后，执行本深化路线，产出**有差异化亮点的作品集**。

## 🎯 阶段 C：检测导航闭环（先做，最快见效）

> 目标：小车"导航到目标 → YOLO 确认 → 报告"完整闭环。感知→规划→执行打通。

### 步骤
```bash
# 1. 前置：基础落地完成（micro-ROS + 建图 + Nav2 导航）
#    见 实机交接-ubuntu.md 阶段 1/2a/2b

# 2. 摄像头 MJPEG 流 → YOLO 检测（detector.py 已准备）
cd robot-real/capabilities/vision
python detector.py --mjpeg http://<camIP>:8080/?action=stream \
    --model /path/to/best.pt   # 钢珠/VisDrone 模型

# 3. 检测结果 → ROS2 话题（桥接）
#    detector.py 输出检测 JSON（类别/置信度/中心坐标）
#    写一个桥接节点: /vision/detections → 导航决策

# 4. 巡检闭环逻辑
#    建图 → 用户指定目标区域 → Nav2 导航 → 到达后 YOLO 确认 → 报告坐标
```

### 作品集产出
- [ ] 完整视频：导航到目标 + YOLO 检测确认 + 报告
- [ ] 检测可视化图（框 + 中心点 + 类别）
- [ ] 流程图（感知→规划→执行 闭环）

### 验证标准
- [ ] 小车到达目标区域
- [ ] YOLO 正确检测目标物并报告位置
- [ ] 端到端稳定运行 ≥3 次

## 🎯 阶段 B：手写算法上真机（差异化核心）

> 目标：path-planning 的手写 DWA 替换 Nav2 默认局部规划器，真机避障。证明"会写算法且能部署"。

### 步骤
```bash
# 1. 手写 DWA 接口（已就绪）
#    path-planning/algorithms/dwa.py
#    DWA(obstacles).plan(state, goal) → (v, w)

# 2. 接入 Nav2 局部规划（controller_server 替换）
#    Nav2 支持自定义 controller（pluginlib）
#    把 DWA 封装成 nav2_core::Controller 插件
#    或用 Nav2 的 nav2_dwb_controller 调手写 DWA 逻辑

# 3. 真机避障对比实验
#    Nav2 默认 DWB/MPPI vs 手写 DWA
#    指标：路径长度 / 时间 / 避障成功率
```

### 作品集产出
- [ ] 真机避障演示视频（手写 DWA）
- [ ] 对比表：手写 DWA vs Nav2（路径质量/成功率）
- [ ] 代码封装（Nav2 controller 插件）

### 验证标准
- [ ] 手写 DWA 真机避障成功
- [ ] 对比表有量化数据
- [ ] 代码可复现
